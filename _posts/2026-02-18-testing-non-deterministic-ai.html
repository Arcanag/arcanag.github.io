01 / The problem

assert == will fail.

Even at temperature 0, outputs drift across API versions and model updates. So teams skip testing — or test the wrong things.

result = generate_tailored_resume(resume, job_description)
assert result == expected_output  # This WILL fail on the next run

Most business logic happens around the LLM call — not inside it.

02 / Four strategies

Test the code. Not the model.

Each strategy isolates something deterministic you can assert on. They come from testing two products: Agentic PM and a resume-tailoring product I built.

  1. 01

    Mock LLM responses

    Most business logic happens around the LLM call. Fix the response with a fixture and test your rules — Agentic PM has 14 of these.

  2. 02

    Test preprocessing separately

    PDF parsing, NER, TF-IDF matching and ATS scoring are deterministic. They run in milliseconds and catch real bugs.

  3. 03

    Validate the schema

    Parse every response against a Pydantic model. Test the well-formed, the malformed — and the polite refusal.

  4. 04

    Test user flows end to end

    Playwright checks that the journey works and something was generated — the plumbing, not the AI.

03 / In practice

A mocked LLM test.

The fixture fixes the model’s answer; the test checks your parsing, aggregation and thresholds.

@patch('agents.decomposition.call_llm')
def test_epic_decomposition_creates_subtasks(mock_llm):
    mock_llm.return_value = {"tasks": [
        {"title": "Design API schema", "hours": 4, "confidence": 0.9},
        {"title": "Implement endpoints", "hours": 8, "confidence": 0.85},
    ]}
    result = decompose_epic("Build user authentication API")
    assert len(result.tasks) == 2
    assert all(t.confidence > 0.8 for t in result.tasks)
    assert result.total_estimate == 12

05 / What not to test

Three tests that only create noise.

  1. 01

    Don’t assert on output quality

    “Should mention Python” breaks the day the model writes “Python 3.x”.

  2. 02

    Don’t test for specific wording

    “Stakeholder management” vs “stakeholder engagement” — both right, both failing.

  3. 03

    Don’t snapshot LLM output

    Golden files work for deterministic renders, not for models.

Test your code. Validate your contracts. Verify your flows. Evaluate your AI separately.

With human judgment and structured eval sets — not with pytest assertions.
